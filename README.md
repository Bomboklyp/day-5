## Что изменилось

- Комментарий получает идентификатор отправки. Повтор после потери ответа не создаёт дубль в базе, версии и истории.
- Новый поиск сразу отменяет старый; поздний ответ не меняет актуальный список.
- Старые ответы сессии и мутаций не восстанавливают состояние после logout. Приватный маршрут и API проверяются отдельно.
- Черновики комментария и новой заявки восстанавливаются после refresh. URL хранит фильтры и страницу, localStorage — плотность списка, sessionStorage — черновики текущей вкладки.
- После изменения заявки списки сверяются с сервером, чтобы строка соответствовала фильтру.
- Добавлены сообщения полей, состояние «Создаём…», сохранение формы при 500 и кнопка «Повторить». При 401 открывается вход, при 409 можно загрузить актуальную версию заявки.

Шаги воспроизведения, причины и соответствующие тесты описаны в **BUGS.md**.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

`typecheck` проверяет приложение и TypeScript-файлы тестов. `lint` использует ESLint с конфигурацией Nuxt и завершается ошибкой также при предупреждениях.

Тесты разделены:

| Папка | Что проверяется |
| --- | --- |
| `tests/unit` | Роли, статусы, пароли, валидация, преобразование API и UI-настройки |
| `tests/integration` | Composables в Nuxt/Vitest, debounce, порядок ответов, logout, черновики и серверный HTTP-сценарий |
| `tests/e2e` | Playwright: полный путь пользователя и регрессии в браузере |

E2E запускается через `npm run test:e2e`: нужен работающий PostgreSQL и Chrome. При другом расположении Chrome задайте `CHROME_EXECUTABLE`. На машине без Chrome можно установить Chromium командой `npx playwright install chromium`.

Запускается собранный Nitro-сервер на порту 3105. Для прогона создаётся временная SQL-схема. Перед каждым браузерным тестом база заполняется заново, а браузер получает чистый контекст. После прогона тестовая схема удаляется. Рабочие заявки не используются для проверок. Требуются права создания схем в отдельной учебной базе.

Порядок ответов контролируется Promise и перехватом HTTP, debounce — виртуальными часами Vitest. Нет `waitForTimeout`, повторных попыток упавших тестов и зависимости E2E от внешних сайтов. Отдельная команда проверки сервера: `npm run test:http`.

Сценарий Playwright: **вход → создание → назначение → смена статуса → комментарий → выход**. Дополнительно проверяются потерянный ответ, устаревший поиск, поздняя сессия, refresh, HTTP 401/409/500 и форма по макету.

## Что нужно понимать

Root cause — причина ошибки, а не её внешний признак. Например, выключенная кнопка защищает от двойного клика, но не от повторной доставки уже сохранённого комментария.

Regression test воспроизводит конкретный случай и проверяет правильный результат после исправления. Unit-тест проверяет небольшое правило; integration-тест — совместную работу частей; E2E — действия пользователя в браузере.

Статусы ошибок: **401** — сессии нет; **409** — конфликт версии или повторное использование идентификатора с другим содержимым; **500** — временная ошибка сервера. Текст формы при ошибке не стирается.
